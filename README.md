# 談藝錄 · 原文與導讀

錢鍾書《談藝錄》的原文選錄與白話導讀，做成一个可以在**原文**与**导读**之间左右对照阅读的静态网页。

在线访问：**https://aureliano-0112.github.io/TalesOfArt/**

网页本身不写死任何篇目——它只读两个文件夹，往里丢 `.md` 文件就会自动出现在目次里，不需要改代码。

| 栏目 | 文件夹 | 现有 |
| --- | --- | --- |
| 原文 | `content/` | 20 篇 |
| 导读 | `interpretation/` | 20 篇 |

---

## 功能

- **两个栏目切换**：左栏顶部「导读 / 原文」标签，点一下即换栏目、换目次、换排版。
- **对照跳转**：两个栏目靠文件名里的节号配对，篇首有「对照原文 / 对照导读」按钮，一键在第一节的原文与导读之间来回跳。
- **按需加载 + 后台预取**：打开页面只加载当前一篇，其余在后台排队取回，首屏很快，全文搜索仍然覆盖正文。
- **全文搜索**：搜篇名、提要，也搜正文；命中正文的条目会标出「正文」徽记。快捷键 `/` 聚焦，`Esc` 清空。
- **阅读偏好**：字号与行宽各自独立可调（行宽以「每行字数」为单位，调字号不会连带改变每行字数），设置存在浏览器本地。
- **键盘翻篇**：`←` `→` 切换上一篇 / 下一篇。
- **原文札记标记**：原文里的 `【补订】`「【补正】」等钱锺书后来添的札记，自动套朱色。

## 本地预览

双击 **`start.bat`**，浏览器会自动打开 `http://127.0.0.1:8760/`。

预览服务每次刷新都重新扫描文件夹，所以新增或修改 markdown 之后按 `F5` 就能看到，**不需要构建**。

> 需要本机装有 Python 3。没有的话装一个即可，或直接看线上地址。

---

## 上传内容（一键脚本）

改完 `content/` 或 `interpretation/` 里的 markdown 之后，双击 **`upload.bat`** 即可。

它会依次：刷新篇目清单 → 暂存这两个文件夹 → 列出本次改动 → 提交 → 推送到 GitHub。推送成功后 GitHub Actions 会自动重建站点，一两分钟后线上就更新了。

命令行用法：

```bash
upload.bat
```

脚本只暂存 `content/`、`interpretation/` 和 `data/manifest.json`，不会误带其他改动。

## 新增一篇

文件名里带上「第几节」就会自动排进目次（支持中文数字一到二十以上）：

```
content/谈艺录_第二十一节.md
interpretation/谈艺录_第二十一节_导读.md
```

两个栏目里**节号相同**的两篇会被认作一对，从而互相跳转。

文件格式：

```markdown
# 《谈艺录·第二十一节》白话导读

> 一句话提要，会显示在目次和标题下方

正文……
```

第一行的 `#` 是标题；紧跟其后的一段 `>` 引文会被当作题记单独排出来。

### 支持的 markdown 语法

标题、引文、表格、有序 / 无序列表、分隔线、`**粗体**`、`*斜体*`、`` `行内码` ``。

## 目录结构

```
TalesOfArt/
├─ index.html                阅读器页面
├─ assets/
│  ├─ app.css                样式：线装书配色、栏目切换、原文与导读的排版差异
│  └─ app.js                 逻辑：栏目切换、按需加载、搜索、阅读偏好
├─ content/                  原文 markdown
├─ interpretation/           导读 markdown
├─ data/manifest.json        篇目清单（构建产物）
├─ site.config.json          站点配置：栏目 ↔ 文件夹
├─ tools/
│  ├─ build.py               扫描 markdown + 组装 _site
│  └─ serve.py               本地预览服务（多一个实时扫描的接口）
├─ start.bat                 双击启动本地预览
├─ upload.bat                双击上传原文与导读
└─ .github/workflows/pages.yml
```

### 想加第三个栏目？

改 `site.config.json` 就行，不用动代码：

```json
{
  "id": "biji",
  "label": "笔记",
  "dir": "notes",
  "lead": "para"
}
```

`lead` 决定目次里那句提要怎么取：`quote` 取标题后的第一段引文，`para` 取标题后的第一段正文。

## 构建

```bash
python tools/build.py
```

做两件事：

1. 扫描两个文件夹，把篇目清单写进 `data/manifest.json`（含每篇的标题与提要，所以网页不用先读完所有 markdown 就能画出目次）；
2. 把网页真正需要的文件复制到 `_site/`，该目录可直接发布。

`_site/` 已被 `.gitignore` 忽略，不必提交——线上由 GitHub Actions 现场构建。

---

## 发布到 GitHub Pages

工作流 `.github/workflows/pages.yml` 已就位。首次配置：

1. 打开仓库 **Settings → Pages**，把 **Source** 选成 **GitHub Actions**。
2. 回到 **Actions** 页面等第一次构建跑完，站点地址形如 `https://<用户名>.github.io/<仓库名>/`。

之后每次 `upload.bat`（或 `git push`），线上都会重新扫描 markdown 并更新。

> 工作流里已经带了 `.nojekyll`，不用担心文件名里的中文和下划线被 Jekyll 拦掉。
